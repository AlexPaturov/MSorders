# Контекст: переход Orders на PostgreSQL

Снимок состояния: 2026-10-31.

## Цель

Перевести микросервис Orders с SQLite на PostgreSQL, полностью убрать SQLite из приложения и тестов, сохранить запуск через Docker Compose и перевести интеграционные тесты на PostgreSQL через Testcontainers.

## Принятые решения

1. PostgreSQL — единственная база проекта; SQLite удаляется из приложения, конфигурации, миграций и тестов.
2. Тесты используют `Testcontainers.PostgreSql` 4.16.0: один общий Postgres-контейнер на прогон, создаётся и удаляется автоматически. Это обеспечивает чистое состояние перед каждым прогоном.
3. API-тесты входят в одну xUnit-коллекцию и используют общий контейнер; миграции применяются при старте приложения.
4. Тесты создают нужные данные сами, используют `Guid`-идентификаторы и не проверяют точные автосгенерированные значения.
5. Compose управляет томом `orders-postgres-data`; имя тома фиксировано через `name`.
6. Секреты передаются через `.env` и переменные окружения; `appsettings.Production.json` в образ не попадает.
7. Для учебного сервиса миграции применяются при старте приложения через `Migrate()`.
8. Режим разработки: Postgres в контейнере, приложение локально под отладчиком; полный compose используется для финальной проверки.

### Решение по миграциям

- **Решение:** применять миграции при старте приложения.
- **Отклонённая альтернатива:** отдельный шаг миграции до запуска сервиса. Для одной реплики учебного сервиса выбран более простой вариант.

## План

1. Запустить Postgres: `docker compose up -d postgres` из `src/`, проверить статус `healthy`.
2. Переключить провайдер: реализовать `UseNpgsql` в `DatabaseOptionsExtensions`, удалить пакет SQLite, секцию `SqLite`, ветку `UseSqlite` и SQLite-настройки из `appsettings*.json`; установить `ActiveDatabase` = `PostgreSQL`.
3. Удалить SQLite-миграции и сгенерировать начальную Postgres-миграцию.
4. Перевести тесты на Testcontainers: добавить `Testcontainers.PostgreSql` 4.16.0, создать `PostgresFixture` и коллекцию, обновить `OrdersApiFactory` и `ThrowingVaultFactory`, удалить SQLite-временный файл.
5. Добавить в `orders-container` переменные `Databases__ActiveDatabase=PostgreSQL` и `Databases__Postgres__ConnectionString=Host=postgres;Port=5432;Database=${POSTGRES_DB};Username=${POSTGRES_USER};Password=${POSTGRES_PASSWORD}`, а также `depends_on` с условием `service_healthy`.
6. Проверить сборку, `docker compose up`, `/health`, CRUD и сохранность данных после пересоздания контейнеров; обновить документацию.

## Следующий шаг

Переключить приложение на Npgsql и удалить SQLite:

1. В `src/Infrastructure/Configuration/DatabaseOptionsExtensions.cs` заменить ветку `UseSqlite` на `UseNpgsql` для `PostgreSQL`.
2. В `src/Infrastructure/Configuration/DatabaseOptions.cs` удалить свойство `SqLite`.
3. В `src/Orders.csproj` удалить пакет `Microsoft.EntityFrameworkCore.Sqlite`.
4. В `src/appsettings.json` и `src/appsettings.Development.json` удалить секцию `SqLite` и установить `ActiveDatabase` = `PostgreSQL`.
5. В `src/compose.yaml` добавить в `orders-container` переменные `Databases__ActiveDatabase=PostgreSQL` и `Databases__Postgres__ConnectionString=...`.
6. Собрать проект через `/usr/bin/dotnet build`.

После этого удалить SQLite-миграции и сгенерировать начальную Postgres-миграцию.

## Правила работы

1. Режим преподавания: объяснения пошагово, один пункт до результата, проверка вывода; код пишется по прямой просьбе.
2. Изменяющие Docker-команды выполняются с явного разрешения пользователя.
3. Сборка, тесты и EF запускаются через `/usr/bin/dotnet` (SDK 8.0.130).
4. Секреты хранятся в `.env`; в документацию и код попадают только имена ключей.
